# CMS Audit — Hound Around Resort (`hound-3`)

**Audited:** 2026-07-10 · **Model:** claude-fable-5 · **Companion file:** `cms-audit/schema-inventory.json`

## Executive Summary

1. 51 schema types registered: 4 documents (`page`, `service`, `testimonial`, `webcam`), 1 settings singleton, 46 objects (41 of them page-builder blocks + `seo`, `button`, `link`, 2 PT types).
2. 3 Portable Text configurations: `blockContent` (rich, custom link annotation + inline image), `blockContentTextOnly` (bare block, *default* link annotation), and an inline PT on `settings.description` (marks-only, used solely as plain text).
3. 8 GROQ queries, all in one file (`frontend/sanity/lib/queries.ts`), all fetched through `next-sanity` Live (`sanityFetch`) — no webhook/revalidate route exists.
4. Live dataset is small and clean: 158 total docs — 7 pages, 3 services, 6 testimonials, 7 webcams, 1 settings, 115 images, **zero drafts** of live types.
5. One orphaned type in the dataset: a single `gallery` draft from a deleted schema type.
6. 18 of 41 page-builder block types have **zero live usage**; 6 individual fields are dead in code (see Dead Fields).
7. No page or service populates its `seo` object — all SEO currently rides settings-level defaults.
8. **Top risk #1:** PT link annotations are silently unrendered in 5 of 7 render sites (bare `<PortableText>` with no components map).
9. **Top risk #2:** pricing lives in two unconnected sources — hardcoded `pricingData.ts` calculators and CMS `pricingPageTabs` display content.
10. **Top risk #3:** deep coupling to Sanity's visual-editing runtime (stega, `useOptimistic`, `dataAttr`, presentation tool) woven through nearly every component.

## Phase 6 — Migration Risk Flags (priority order)

1. **HIGH — Unrendered PT links in 5 of 7 render sites.** Bare `<PortableText>` without a components map means the custom link annotation renders as plain text in SplitContent, FaqAccordion, FeatureList, ContentColumns, ContactForm. Unify the renderer in embark-os and audit existing content for links editors think are live. (`sections/SplitContent.tsx:58` et al. vs `PortableText.tsx:97-101`)
2. **HIGH — Dual-source pricing.** Calculators read hardcoded `app/data/pricingData.ts`; displayed tables read CMS `pricingPageTabs`. Known operational hazard (price updates need both). Embark-os should make pricing single-source.
3. **HIGH — Visual-editing coupling.** `defineLive`/`sanityFetch` on every fetch, stega + `stegaClean()` in 15+ components, `useOptimistic` reconciliation in PageBuilder, `dataAttr` overlays in BlockRenderer, presentation tool in two configs. Decide early whether embark-os replicates live preview or all of this is stripped.
4. **MEDIUM — Three link shapes, one resolver.** blockContent annotation (`{linkType,href,page→page}`, init href) vs blockContentTextOnly default annotation (`{href}`) vs standalone `link` (`{linkType,href,page→page|service,queryString}`, no init). Normalize to one shape on migration; resolve dirty data by `linkType` and drop the losing branch.
5. **MEDIUM — JSON-LD `_ref`-as-URL bug** (`layout.tsx:84-89,184-186`) — currently latent (logo unset); fix in the rewrite.
6. **MEDIUM — Image pipeline reproduction:** sanity-image srcset/auto-format at 16 widths with crop+hotspot; 1200×627 OG crop; 1600w lightbox that derives natural dimensions from the asset-ID filename pattern — breaks if new asset IDs don't encode dimensions.
7. **MEDIUM — Typegen dependency:** `predev`/`prebuild` run Sanity schema extract + typegen; component prop types derive from GROQ result types (`ExtractPageBuilderType`). Embark-os needs an equivalent type story for 41 block shapes.
8. **LOW —** Orphaned `gallery` draft; blockContent inline images can't have alt (schema has no field, renderer reads one); Studio features needing replacement decisions (AI Assist, Unsplash source, Vision, presentation `post` leftovers in config); dead fields (Phase 2 table) and 18 unused block types — candidates to drop, not migrate; `@portabletext/react` phantom dependency; two public-folder hero illustrations outside the CMS.
